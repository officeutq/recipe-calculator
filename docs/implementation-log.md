### 実装内容（事実）

- `new/edit` 画面の `RecipeForm` で基準分量欄を「基準分量: [入力欄]」の1行表示に変更した。
- 基準分量入力は既存の `NumberInputModal` 連携（readOnly入力をタップしてモーダルを開く挙動）を維持した。
- 材料カード内の `編集` / `削除` ボタンをアイコン（`✏️` / `🗑️`）表示に変更した。
- アイコンボタンに `aria-label="材料を編集"` と `aria-label="材料を削除"` を付与した。
- アイコンボタンを小さめの角丸ボタンとしてスタイル定義し、`min-width` / `min-height` を設定してタップしやすさを維持した。
- `field--inline` を追加し、通常は1行表示・狭い幅では自然に折り返すレイアウトにした。

### 学習ポイント（事実）

- モーダル起点の入力欄は、見た目だけを inline 化しても既存ロジックを壊さずUI調整できる。
- 文字ボタンが改行する問題は、アイコン化と最小タップ領域の明示で可読性と操作性を同時に改善できる。
- アクセシビリティはアイコン化時に `aria-label` を付与して担保するのが有効。

### 確認内容（事実）

- `npm run build` を実行し、TypeScript コンパイルと Vite ビルドが成功した。
- 変更対象が `RecipeForm` とそのスタイルに限定され、`calculator` 画面・`IngredientFormModal`・`NumberInputModal`・保存処理・LocalStorage 処理を変更していないことを確認した。

### 次にやること（推測）

## 現在の実装概要（事実）

- React + TypeScript + Vite の単一ページ構成。
- 画面モード切替で `calculator` / `new` / `edit` を表示する。
- `new/edit` の `RecipeForm` はレシピ名・説明・基準分量・材料一覧編集・保存操作を担当する。
- 数値入力は `NumberInputModal`、材料追加/編集は `IngredientFormModal` を利用する。

## 現在の画面構成（事実）

- ヘッダー
  - アプリラベル
  - タイトル
  - 説明文
- `calculator` 画面
  - レシピ選択
  - 新規作成/編集ボタン
  - 基準分量と今回の分量入力
  - 材料一覧（換算結果）
  - 説明表示
- `new` / `edit` 画面（`RecipeForm`）
  - レシピ名入力
  - 説明入力（textarea）
  - 基準分量行（`基準分量:` + 数値入力欄）
  - 材料見出し行（`材料` + `材料追加`）
  - 材料一覧（各行に編集/削除アイコンボタン）
  - 保存/キャンセル（編集時は削除も表示）
- モーダル
  - `IngredientFormModal`
  - `NumberInputModal`
